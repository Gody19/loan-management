# Phase 11.9 — Proactive Intelligence (Rules, Alerts & Actionable Insights)

**Start:** after Phase 11.8 commit `10acd81`
**Scope:** advisory "what should I act on right now" alerts for the operator — overdue exposure, maturity pressure, portfolio-at-risk and concentration, projected cash-flow shortfalls, collection and savings declines, accounting drafts, operational gaps and predictive-outlook warnings — raised by deterministic rules over authoritative FinancePro records, persisted as idempotent, deduplicated, tenant-scoped `ai_insights` rows, surfaced on the Phase 11.7 Financial Intelligence dashboard, exposed to the AI chat as a read-only capability, delivered as in-app database notifications, generated by a scheduled command, fully audited.
**STOP rule honored:** no machine-learning models are trained or hosted; insights never change a financial record and never make or influence an automated decision (approval/eligibility/rate/ledger/repayment); acknowledge/resolve/dismiss are exclusively human dashboard actions; no member-portal or public landing-page surface can reach this layer; no new auth layer and no breaking changes to existing AI security.

## 2. Scope & design decisions

- **Rule-based, deterministic advisories.** Ten rules run against authoritative records (`Loan`, `LoanRepaymentSchedule`, `LoanRepayment`, `SavingsTransaction`, `JournalEntry`, `LoanApplication`, `DataQualityService`, `CashflowForecastService`, `PredictiveIntelligenceService::latest`). Each rule emits a payload keyed by a stable dedup identity. The layer is purely advisory and read-only — queries never write to a financial table.
- **Rule catalog** (each maps to a `ProactiveInsightType`):
  - `overdue_loan` — an active loan with an outstanding installment overdue at least `overdue_min_days` (severity: notice/warning/critical at the config breakpoints).
  - `portfolio_concentration` — a single loan holding `concentration_ratio` or more of total active outstanding principal (warning).
  - `maturity_pressure` — at least `maturity_concentration` active loans maturing inside `maturity_window_days` (notice).
  - `portfolio_par` — delinquent principal past `par_threshold_days` reaching `par_warning_percent` / `par_critical_percent` of total principal (notice/warning).
  - `cashflow_shortfall` — the Phase 11.8 cash-flow forecast's projected cumulative net below `cashflow_shortfall_threshold` (warning).
  - `collection_decline` — the current complete month's collection rate at least `collection_decline_points` below the previous month (warning).
  - `savings_decline` — trailing-window deposits below `savings_decline_percent` of the previous equal window (notice).
  - `accounting_draft_entries` — journal entries in draft for at least `journal_draft_days` (notice); an unbalanced trial balance raises a warning.
  - `operational_pending_applications` — submitted-but-pending applications for at least `operational_pending_days` (notice); data-quality issues reported by the quality gate (notice).
  - `predictive_delinquency_risk` / `predictive_quality_gate` — the latest delinquency-risk snapshot above the medium/high thresholds (warning) or a `poor_quality_data` snapshot (notice).
- **Deduplication semantics.** Every row carries `dedup_key = org | branch | rule | source_type:source_id | period_start`. A re-detected condition updates the same row; a **dismissed** row is never overwritten; a **resolved/expired** row whose condition re-occurs **reopens as `new`** (human timestamps cleared). A database unique constraint on `dedup_key` makes concurrent passes race-safe.
- **Domain-driven expiration.** An open insight whose condition is no longer produced by the current rule set **and** whose `generated_at` is older than `stale_after_days` (7) is retired to `expired` with `expired_at`. This bounds the open list and prevents flapping, without ever revoking a human decision.
- **Lifecycle is human-only.** `new → read → acknowledged → resolved` and `new → read → dismissed` (dismissed is permanent for that condition). The AI model can only *read* open insights; acknowledging/resolving/dismissing happen on the dashboard with an explicit actor and audit.
- **Notifications on creation.** A brand-new insight dispatches a Laravel **database notification** to every user holding `ai.insights.view` in the owning organization. Functioning while `proactive-intelligence.notify` is true (default).
- **Org-level, branch-capable.** Detection accepts an optional branch filter; the dashboard and tool derive branch scope exclusively from the trusted `AiContextData` (org-level insights with a null branch are always visible to an authorized org holder).

## 3. Configuration (`config/proactive-intelligence.php`, env `AI_INSIGHTS_*`)

| Key | Default | Meaning |
| --- | --- | --- |
| `enabled` | `true` | master switch for the whole layer |
| `notify` | `true` | in-app notification for each new insight |
| `stale_after_days` | `7` | open insights retire after this many days without regeneration |
| `max_per_organization` | `50` | upper bound persisted per org per pass (severity-ordered) |
| `overdue_min_days` / `overdue_warning_days` / `overdue_critical_days` | `7` / `30` / `90` | overdue severity breakpoints |
| `maturity_window_days` / `maturity_concentration` | `30` / `3` | maturity cluster |
| `par_threshold_days` / `par_warning_percent` / `par_critical_percent` | `30` / `5.0` / `10.0` | portfolio-at-risk |
| `concentration_ratio` | `0.30` | loan concentration share |
| `cashflow_shortfall_threshold` | `0` | projected-net liquidity floor |
| `collection_decline_points` | `20.0` | collection-rate drop threshold |
| `savings_window_months` / `savings_decline_percent` | `3` / `20.0` | savings-deposit decline |
| `journal_draft_days` | `7` | stale journal drafts |
| `operational_pending_days` | `5` | stale pending applications |

Every knob is env-driven (`AI_INSIGHTS_*`); `.env.example` carries the block. Changing a knob changes only what the advisory layer reports.

## 4. Persistence & lifecycle

- Migration `2026_09_29_000001_create_ai_insights_table` → `ai_insights` (unique `dedup_key`, composite `(organization_id, status, generated_at)` index, `type`, `severity`; `nullableMorphs('object')` provides `object_type`/`object_id`; person/pivot columns `acknowledged_by` etc. FKs onto `users`, nullOnDelete).
- Migration `2026_09_29_000002_create_notifications_table` → standard Laravel database-notification table.
- `AiInsight` model with enum casts (`type`, `severity`, `status`, `source_type`), date/datetime casts, morph `object`, person relations, and `forOrganization`/`forOrganizations`/`open` scopes.
- Enums: `ProactiveInsightType`, `ProactiveInsightSeverity` (info/notice/warning/critical + `priority()`), `ProactiveInsightStatus` (new/read/acknowledged/resolved/dismissed/expired + `isOpen()`), `ProactiveInsightSource`.
- `ProactiveInsightService`:
  - `generate()` — runs detection, persists each raw under its dedup key (reopen-or-update, dismissed-immunity, unique-race fallback), expires stale rows, audits `ai.insights.generated` (rules, created/updated/expired/active) and dispatches notifications;
  - `runForOrganizations()` — scheduler entry point aggregating the pass summary;
  - `expire()` / `expireFor()` — domain-driven retirement;
  - `forDashboard()` — open insights for the trusted context, severity-first, eager-loaded, branch-filtered;
  - `acknowledge()` / `resolve()` / `dismiss()` — human transitions (no-op outside their guards), each audited (`ai.insight.acknowledged|resolved|dismissed`) with before/after status and actor.
- `AiInsightNotification` — database-notification payload (insight id, severity/type labels, title, summary, url → `ai.intelligence.index`).
- The detection service is a pure read: it uses builder predicates and service facade calls, never raw SQL, never a mutation.

## 5. Data sources (authoritative operational tables)

- Loans / schedules / repayments / savings transactions / journal entries / applications: direct where-clause reads with branch filters via `branch_id`.
- Data quality: `DataQualityService::issues()` reuse for the operational quality-gate rule.
- Cash flow: `CashflowForecastService::predict()` (Phase 11.8) — voided by `try/catch`; only a `generated` outcome below the floor is raised.
- Predictive outlook: `PredictiveIntelligenceService::latest()` per domain; a `poor_quality_data` snapshot raises the quality gate, otherwise only `DelinquencyRisk` with a score above the threshold raises an insight.

## 6. RBAC, orchestration, dashboard, scheduler & inbox

- Single permission **`ai.insights.view`** granted by the seeder to Organization Administrator, Branch Manager, Loan Officer, Credit Officer, Collection Officer, Treasurer, Accountant, Auditor. **Not granted** to Secretary or VICOBA Member; Super Administrator receives everything.
- Registry: `ai.insights.view` is a user-org-scope, zero-argument, read-only capability (21st business capability). `ProactiveInsightsTool` serializes open insights (id, org/branch, type/severity/status with labels, title/summary/recommendation, source, period window, data-through, generated-at, `open` flag) plus an `open_count` and an explicit "human decision" note.
- `AiInsightResultFormatter` emits a `<FINANCEPRO_INSIGHT_DATUM>` block with an explicit advisory caveat; `AiController::formatResult()` routes it for both `/ai/tool` and the orchestrated flow.
- Orchestrator keywords `insight`, `proactive`, `action item`, `priorit`, `focus on` attached to the `ai.insights.view` entry, placed **last** in `ORGANIZATION_INTELLIGENCE` so earlier Phase 11.7/11.8 matches win; label `proactive insights and alerts`.
- Dashboard `GET /ai/intelligence` (permission OR-list now includes `ai.insights.view`): renders a "Proactive insights & alerts (Advisory)" card between the predictive and portfolio cards — open insights severity-first with title, summary, recommendation, metadata, and **Acknowledge / Resolve / Dismiss** actions. Actions are `POST` routes (`ai.intelligence.insights.{acknowledge,resolve,dismiss}`) gated by the same permission + `throttle:ai.tool`, tenant-checked in the controller (cross-org → 403). The dashboard empty-state only appears when the holder has no data at all.
- Notifications: global **Inbox** at `GET /notifications` (`notifications.index`), `POST /notifications/read-all` (`notifications.read-all`), `POST /notifications/{notification}/read` (`notifications.read`) — the latter guards `notifiable_type`/`notifiable_id` (foreign rows → 404). The bell in the navbar shows the real unread count + latest five with a "View all" link; the sidebar gains a Notifications item with an unread badge.
- `Console\Commands\AiGenerateInsights` (`ai:generate-insights`, optional `--organization=`) runs `runForOrganizations()`; scheduled daily at `04:00` in `routes/console.php` (after loans `01:00`, cleanup `02:00`, predictions `03:00`).

## 8. Known limitations & deferred work

- Rules run on the daily scheduler at a fixed time; a repository-change-triggered instant regeneration is not shipped (the scheduler pass is idempotent, so operators can also run `php artisan ai:generate-insights --organization=1` on demand).
- Insights are bounded per organization per pass (`max_per_organization`, severity-ordered); extremely large loan books under heavy distress will surface the bound's slice first.
- Notification delivery is strictly on creation; resolving the underlying condition expires the insight but does not auto-mark its notification rows read.
- Per-branch insight rows are advisory scope filters today; a branch lookup only ever reads org/branch rows it is allowed to see (`whereNull('branch_id')->orWhereIn('branch_id', …)`).
- No ML, no member-facing exposure, no automated action on an insight — those remain explicit extensions, consistent with the Phase 11 STOP rules.
